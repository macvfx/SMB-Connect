-  v0.7.5 beta (build 28) adds fleet tooling for CopyTrust volume requests. The CSV generator and JSON-to-profile converter preserve each share's default-off approval, and the validator refuses a profile when a required Mount Name is absent, duplicated, or not explicitly enabled.
-  v0.7.5 beta updates Mount Import Assistant to export the approval in its JSON, CSV, and review report, and includes a tested Swift reference client showing how CopyTrust requests a volume and checks its own folder without receiving credentials or endpoint details.
-  v0.7.4 beta (build 27) lets another app request a required volume through a versioned `smbconnect://v1/mount` URL using the share's unique **Mount Name**. The request carries no server address, username, or password: SMB Connect resolves the configured share and chooses the best reachable preferred or fallback network path. Each share must explicitly allow requests from other apps.
-  v0.7.4 beta makes the original SMB Connect app the mounting and Keychain authority. SMB Connect Desktop delegates mount requests to it when available, avoiding a second app asking users to grant or re-enter the same saved passwords. The original app can now optionally show a Dock icon and full window for laptop users who prefer not to spend menu bar space.
-  v0.7.4 beta renames diagnostics to **Export Logs and Diagnostics** and makes the export available from the Help menu as well as Settings.
-  v0.7.3 beta (build 26) adds **Switch to Preferred**. When a share is mounted on a fallback path and the faster one comes back, the button on that share now says what it will do — disconnect the share and mount it once on the preferred network — instead of a generic *Fix Connection*. It only says **Switch to Preferred** when the preferred path really is the one it will use; if your fastest network is still down and only a middle fallback is available, the wording stays generic, because the share is not going where the other label would suggest. It asks before it does anything: quit Final Cut Pro and anything else with files open on that share first.
-  v0.7.3 beta records what it does, so a problem can be looked into after the fact rather than reproduced. It logs every connection state change, the network path chosen for each share, and every mount and unmount together with what asked for it — including the mounts and unmounts macOS performs on its own, which is what tells you whether shares dropped because the app disconnected them or because the network did. **Export Diagnostics** in Settings writes that log, your configured shares, the live network interfaces and the current mount table into one text file, ready to send. No passwords and no account names are in it.
- *FIXED* v0.7.3 beta stops a failed reconnect from leaving a share unmounted. Automatic reconnection, and the repair button, both used to disconnect the share first and only then look for a saved password and a reachable server — so if either was missing you were left with no mount at all, having had a working one moments earlier. This was most likely exactly when it hurt: while a Mac changes network, every configured path is briefly unreachable, so every share could be taken down at once. Both now check they can reconnect before disconnecting anything, and say so when they decline.
- *FIXED* v0.7.3 beta makes the app far quicker to notice a server that is not answering. Checking whether a share's server was reachable waited a second and a quarter before giving up, even when the server had already refused outright — which it does immediately when it is switched off. That check now returns as soon as the answer is known. It matters most while a Mac is changing network, when the old behaviour could leave the app busy for fifteen seconds at a time.
- *FIXED* v0.7.3 beta fixes a crash and a freeze around saved passwords. Reading a password from the Keychain was done on the part of the app that draws the window, so the Settings window locked up for as long as the standard macOS *Always Allow* prompt was on screen — the one you see the first time the second app reads a share the first one saved. Separately, status checks could overlap and run into each other, which could crash the app outright; they no longer can.
- *FIXED* v0.7.2 beta (build 22) makes the status colours say one thing at a time. A share connected on its **fallback** path showed an orange check mark — a warning colour on the icon that means "connected", repeating what the orange **Fallback** label beside it already said. A green check now always means connected, and only the wording turns orange. An **offline** share is grey rather than red and no longer counts as needing attention: a server that is switched off, or being away from that network, is not something you can fix.
- *FIXED* v0.7.1 beta (build 21) makes **Connect All** work in SMB Connect Desktop. In 0.7.0 the `Shares` menu decided once at launch — before the app had finished looking at your network — whether anything was connectable, and never checked again, so **Connect All** and **Disconnect All** were greyed out for as long as the app was open. Connect All is also a properly labelled toolbar button now rather than an unlabelled icon.
-  v0.7.0 beta (build 20) adds **SMB Connect Desktop**, a second app with a Dock icon and a proper window — shares down the left, and the selected one filling the right with the things the menu bar popup has to shorten: the full explanation when another user holds a volume, every configured network path with the one in use marked, and the complete repair guidance. Closing its window does not quit it. Both apps share one configuration and are built to run side by side.
- *FIXED* v0.7.0 beta warns properly when you are on **Wi-Fi with no wired connection**. The banner previously only said anything when the Mac had no network at all, so a Wi-Fi-only Mac saw a reassuring blue "Active Networks". Shares mount fine over Wi-Fi — that is why it is worth flagging, because everything on them is simply far slower than the `1GbE` or `10GbE` path they are configured for.
-  v0.6.0 beta (build 19) says when **another user logged in on this Mac** already has the share mounted — naming who has it, whether they are still logged in, and where — instead of reporting a folder to rename that belongs to another account and cannot be opened from your session. A `/Volumes` path is claimed once for the whole Mac, not once per user.
-  v0.6.0 beta detects **one server mounted through two different addresses** — its IP and its Bonjour `.local` name, which is what the Finder's **Network** sidebar uses. macOS cannot tell those are the same machine, so mounting through both gives you two volumes and the second gets a `-1`. The share now names both addresses, and `Fix Connection…` clears it.
